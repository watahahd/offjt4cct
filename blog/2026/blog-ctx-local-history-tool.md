# 30日で消えるAIの履歴を救う！ローカル履歴永続化ツール「CTX」の紹介

## 1. 導入 (WHY)

日々の開発でAIツールを活用する中で、以下のようなお悩みはありませんか？

- Claude Codeの履歴が30日で自動的に消えてしまい、過去の対話が振り返れない
- 「前にも同じエラーで詰まったのに、あの時どう解決したか思い出せない…」と悔しい思いをする
- Codex と Claudeを使い分けているため、「あの回答、どっちのAIから貰ったっけ？」と探すのが大変

せっかくの試行錯誤が流れて消えてしまうのは、非常にもったいないですよね。
  
そんなお悩みを前向きに解決してくれるのが、今回ご紹介するローカル履歴永続化ツール「 **CTX** 」です。

CTXを取り入れることで、消えてしまう履歴を「再利用できる資産」へと変えることができます。

### CTX導入前後の比較

| 項目 | CTX 導入前 | CTX 導入後 |
| :--- | :--- | :--- |
| **履歴の保持** | Claude Codeは30日で自動削除 | SQLiteに永久保存 |
| **検索範囲** | ツールごとに画面を巡回 | `ctx search` で横断一括検索 |
| **エージェント連携** | 手動で過去の回答をコピペ | MCP経由でAIが自律参照 |

## 2. 本論 (WHAT & HOW)

### CTXとは？ 履歴を資産に変える仕組み

CTX は、Claude Code や Cursor、Codex などのコーディングエージェントがローカルに保存しているセッション履歴を、ひとつのSQLiteデータベースにまとめてくれるCLIツールです。

> 💡 **用語解説: SQLite（エスキューライト）**<br>
> アプリに組み込んで使える、セットアップ不要で軽量なデータベースのことです。

Claude Codeは通常、`~/.claude/projects/` 配下にJSONL形式でログを出力しますが、これらはデフォルトで30日経過すると削除されてしまいます。

CTXはこれらの履歴をSQLiteに永続化し、高速に検索できるようにしてくれます。

### Codex と Claudeのログを共通サーチできる強力なメリット

私が実際にCTXを使ってみて最も感動したのは、 **CodexとClaudeのログを共通でサーチできる** 点です。

複数のAIツールを適材適所で使い分けることが日常的になっていると

-  あのコードはどのAIが出してくれたんだっけ？
-  この仕様に決まったのってなんでだっけ？
-  同じ作業させたいけど手順どこいったっけ？

と複数の画面を行き来するのは手間でした。

CTXを使えば、過去の知見を一つのコマンドで横断検索でき、生産性が大きく向上します。

> 💡 どのツールの履歴に対応しているの？<br>
> CTXは、各AIツールがローカルに保存しているデータベース（SQLiteなど）やネイティブのログフォーマットを自動で読み取り、検索可能なインデックス（Tantivy）を構築します。<br>
> Cursor、Claude Code、Windsurf、Zed、GitHub Copilot CLIなど、40種類近いツールのローカル履歴に対応しており、クラウドにデータを送信することなく安全に検索できます。

### 導入と検索のハンズオン手順

以下は、実際にCTXを導入して検索を行うための手順です。

#### 1. CTXのインストール
```bash
# 公式スクリプトでインストール（macOS/Linux環境の場合）
curl -fsSL https://ctx.rs/install | sh
```

#### 2. 履歴の同期と検索
```bash
# 既存のローカル履歴をインデックス化
ctx setup

# "マイグレーション 失敗" というキーワードで横断検索
ctx search "マイグレーション 失敗"
```

#### 3. 期待される実行結果ログ
```text
Found 2 results:
[Claude Code] 2026-08-01: ...マイグレーション失敗の解決策は...
[Codex] 2026-08-03: ...以前のマイグレーションエラーについて...
```

### エージェントからMCPサーバーとして利用する（おすすめ）

CTXはCLIツールとしてだけでなく、 **MCP（Model Context Protocol）サーバー** としても機能します。

日常的に Claude Desktop や Cursor、Codex などのAIコーディングエージェントを使用している方には、こちらの利用方法が圧倒的におすすめです。

各ツールの設定ファイル（例: `mcp-servers.json` やCursorの設定画面）にCTXを登録することで、AIエージェント自身がシームレスにあなたの過去の履歴を検索・参照できるようになります。

これにより、エンジニアがわざわざターミナルで `ctx search` を叩かなくても、AIが自動的に過去の失敗や文脈を読み取って回答してくれます。

**設定例 (mcp-servers.json 等)**
```json
{
  "mcpServers": {
    "ctx": {
      "command": "ctx",
      "args": ["mcp"]
    }
  }
}
```
※ご利用のツールの仕様に合わせて設定してください。

> 💡 Tips<br>
> 明示的に使いたい場合は「ctxを使って⚪︎⚪︎を探して」のように指示する感じで利用できます。 <br>
>  個人的にはその日の作業リスト化や、再テスト指示で「⚪︎⚪︎を△△の条件でテストして」みたいに使っています。<br>
> （毎回プロンプトやコマンドを打ち直さなくてもよくなります）

### 導入時の注意点とベストプラクティス

とても便利なCTXですが、導入にあたって1点だけ気をつけるべきことがあります。

それは、CTXが「マシン上の履歴を丸ごと索引化する」という特性を持っている点です。

- **複数プロジェクトの混在**<br>
  個人開発と業務コードが同居しているPCはもちろん、会社PCで複数のクライアント案件を掛け持っている場合、他プロジェクトの機密情報が検索結果にヒットする可能性があります。
- **機密情報・APIキー**<br>
  ターミナル出力などに含まれるAPIキーやパスワードもそのままインデックス化されるため、MCP連携時にAIへ送信されるリスクがあります。

そのため、まずは個人利用の範囲で試すか、会社のセキュリティ規定を確認した上で、自分専用の知識ベースとして活用するのがおすすめです。
